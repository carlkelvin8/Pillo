# Phase 5 MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver scoped MCP access, token management, eight MCP tools, staff-approved payment requests, and audit logging.

**Architecture:** Use a stateless MCP Streamable HTTP route authenticated by hashed clinic bearer tokens. Use Drizzle with explicit clinic predicates for server-side MCP database work; keep token management and approvals in authenticated owner/staff flows.

**Tech Stack:** Next.js 15 route handlers, MCP TypeScript SDK, Drizzle/Postgres, Zod, Supabase migrations, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-25-phase-5-mcp-design.md`

## Global Constraints

- Every table is scoped by `clinic_id`; RLS enforces it.
- Hand-written SQL migrations are source of truth.
- Never log patient names or contact details.
- Do not expose service role or database credentials to clients.
- Do not add money-sending tools; payment requests require staff approval.
- Do not apply migrations to live Supabase.

## Review Focus

- Revoked or wrong-scope tokens cannot call tools.
- Patient search/summary requires explicit `patients:read` and returns no clinical notes.
- Every authenticated success/failure gets a redacted audit record.
- MCP payment requests cannot create links without a staff approval action.
- Tenant filters prevent cross-clinic reads/writes.
